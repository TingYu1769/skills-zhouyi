# 行为验收场景

维护者用场景；执行时加载技能入口及相应参考说明，素材放在临时工作目录。

## 0. 首次运行的环境检查

从缺少 PyMuPDF 和 Pillow 的 Python 环境运行 `preflight.py`，确认能给出缺项；在隔离环境中准备依赖后重新运行。另行检查版本不兼容、导入失败、输入无法读取和输出路径不可写的情况。

使用实际 PDF 验证渲染，并由 agent 打开预览。宿主图像工具不可用时，指出需要启用的能力，保持任务待开始。记录检查与准备结果后进入翻译。

## 1. 完整虚构论文

用 `make_fixture.py` 生成四页论文。要求从标题翻译到扫描页末尾，保留英文参考文献，整理图表、算法和提示词。

检查双栏顺序、限定语、数值、脚注、跨页表末行与表下注释；旋转图四角标签完整；公式编号、提示词变量和 JSON 字段保留；扫描页的代码原样复制。全部输出图片逐张查看。

## 2. 中断与恢复

翻译到方法章节时保存进度和术语，重新运行 `inspect` 后续作。核对既有章节、术语及图片复核记录保持不变。换用改过的 PDF 时，应识别源版本变化。

## 3. 裁剪纠正

先生成一个缺少末行或脚注的截图，打开后指出具体缺失。扩大区域重裁，重新查看图片。确认工作记录恢复为待复核，再写入本次检查结果。

## 4. 不清晰的原文

使用模糊图表及无法辨认的正文样例。图表扩大范围或保留整页；原文仍不清晰时保留图注与约定提示。正文记录页码和待确认内容，保存已完成工作，报告实际完成范围。

## 5. 文件与交付

完成全文核对后校验并打包。移动目录或解压到另一位置，检查相对图片引用仍有效。再次编辑 Markdown 或图片时，复核记录应反映变更。

## 6. 真实论文全文

选择一篇本地公开论文，从输入 PDF 开始执行全文翻译，交付 Markdown、原 PDF、全部图表和 ZIP。覆盖作者信息、正文、脚注、参考文献与末尾附录，按原文建立清单并逐项核对。检查数字、限定语、引用顺序和公式，逐张打开最终截图。

使用支持数学公式的 Markdown 渲染器检查实际输出，确认脚注仍显示原编号、所有图片加载成功。中途保存并恢复一次任务，完成后解压到另一目录验证。记录真实覆盖范围和发现的问题，原论文及译文保存在实验工作区。

## 7. LaTeX 源码模式

选一篇有公开源码的 arXiv 论文，按 PDF 首页的版本号取源码包。先运行 `preflight.py --tex`，再执行 `tex-prepare` 与 `tex-build`，把英文底稿与原 PDF 逐页比对，确认公式符号、作者标记和页数一致；字形有误时先修环境或加手工修正，再切块。

逐块翻译、写完即核对，执行 `tex-merge` 与 `tex-build`。故意写坏一块（例如删掉一个占位符或漏掉花括号），确认合并检查拒收；再写一块能通过检查但会让编译失败的译文，确认只有这一块退回英文、对应章节回到待处理。修好后重新编译，渲染全部页面拼图检查版面，查看模板写死的标签、作者说明和外部文件里是否留有英文。最后执行 `tex-deliver` 与 `tex-check`，把 `zh-tex/` 复制到另一目录单独重编。
