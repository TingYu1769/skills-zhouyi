# 翻译与排版

## 内容覆盖

按原文顺序处理标题、作者与单位、摘要、正文、脚注、致谢、局限性、参考文献、附录及补充材料。作者姓名、邮箱、URL、代码标识符保留原样；单位和自然语言说明可译成中文。正文与附录执行同一完整性标准。

译文完整表达原文，不缩写成摘要，不为作者增加例子、解释或推论。证据强度、否定、比较对象、适用条件及作者归因都保留。提取造成的断词、换行和双栏串行应结合原页还原；遇到原文疑误，在工作记录中列出位置和疑点，译文忠实呈现可确认的内容。

在 `progress.json` 的 `sections` 中登记每节的来源页，并在 `note` 里写明容易遗漏的内容：短段、脚注、公式、页间断句、图表和参考文献之后的材料。长节或难节需要细分时，再登记内容单元，例：`p1`（段落）、`eq1`、`footnote1`、`fig1`。清单由原 PDF 建立，不能只从已写译文反推。

## 术语与原始标记

- 重要术语首次出现用“中文（English）”，缩写一并介绍，后续保持一致。
- 模型、方法和数据集名称采用原文名称，必要时附中文解释性译名。
- 引用保持 PDF 实际呈现的作者、年份、编号和括号样式。例如 `[1, 3]`、`(Lee et al., 2025)`。源材料若直接包含 `\cite{key}`，原样保存。
- 列表、编号、脚注标记、公式编号、附录字母及交叉引用对应原文。
- References/Bibliography 保留完整英文条目和 URL，放在原文对应位置。

脚注保留原始标记和相对位置。数字脚注可写为正文中的 `<sup>4</sup>`，对应说明写成 `**4** 说明文字`；星号、剑号等符号按原文保留。标准 Markdown 的 `[^4]` 标签常会被渲染器重新编号为 1，因此交付前要核对实际显示的编号。

## 标题

```markdown
# 中文标题（English Title）

## 摘要（Abstract）

## 2. 方法（Method）

### 2.1 训练过程（Training Procedure）

**采样策略（Sampling Strategy）** 正文……

## References

## A. 附录标题（Appendix Title）

### A.1 补充实验（Additional Experiments）
```

使用最多三级 Markdown 标题。保留原文 section 和 subsection 的编号；更深层标题以及 `\paragraph{}` 改为无编号的段首加粗。标题、摘要和原本未编号的章节不另加编号。

## 公式与代码

行内数学使用 `$...$`。独立公式的 `$$` 单独成行，可用 `\tag{1}` 保存原公式编号。以原 PDF 核对上下标、求和范围、括号、粗体向量、希腊字母和符号方向。

代码使用带语言标记的代码块，保留可执行内容、注释、字符串和缩进。提示词放在 `text` 代码块中：翻译自然语言，保留变量、占位符、标签、命令、JSON 字段名及格式示例中会被程序读取的字面值。原文讨论这些字符串本身时，原样保留，并翻译周围说明。

算法保留原始截图，另附中文步骤或 `text` 伪代码，保持输入输出、步骤编号、分支、循环、变量和数学表达式。算法里出现的自然语言说明完整翻译。

## 图片与图注

```markdown
![图 1](assets/fig_01.png)

*图 1：这里是图注的完整中文翻译。*
```

表格同样以原 PDF 截图呈现；图表内部标签和数据保留原始画面。图注与表注的标题、解释和限定条件完整翻译，放在图片下方，使用斜体。表下注释若属于说明文字，截图保留它，并在中文说明中译出。

保持图片在所属章节和论述中的相对位置。跨页对象依次引用各部分，避免把续表说明遗漏或重复成两份完整图注。算法和提示词框的中文文本放在截图及图注之后。
