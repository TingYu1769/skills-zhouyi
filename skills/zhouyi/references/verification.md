# 验收与恢复

## 逐项核对

全文检查从原 PDF 的章节清单出发，逐项找到译文中的对应内容。

1. **结构与覆盖**：作者信息、摘要、正文、脚注、致谢、局限性、参考文献及全部附录均有对应。逐段检查双栏顺序、跨页接续和嵌入的列表。
2. **信息**：数字、单位、数据集规模、基线、比较对象、实验条件、否定和证据强度保持原意。保留原文的归因和引用。
3. **符号**：逐式检查变量、上下标、求和范围、函数、矩阵、括号及公式编号。代码和占位符与原文一致；检查 Markdown 渲染后的脚注标记是否保持原编号。
4. **文字**：重要术语首现有英文，全篇译名统一；正文是完整译文，参考文献保留英文。
5. **图表**：每张实际输出图片都已打开并与原页对照；跨页部分连续，图注、表注及脚注完整。
6. **文件**：运行 `check`，核对原 PDF 哈希、图片路径及 Markdown 结构。可复制目录到临时位置检查图片引用。

脚本验证记录与文件是否一致；agent 根据实际对照结果填写复核状态。页面已覆盖是清单检查，不能代替逐段对照。

## 中断后继续

从工作目录读取 `progress.json`：

- 用输入 PDF 重跑 `inspect`，核对源文件身份。
- 读取术语表、未完成章节、待处理问题及图片状态。
- 保留已完成部分，从待处理单元继续；重读前后相邻段，保持跨页句子与术语连续。
- 图片重新裁剪后重新查看；Markdown 改动后重新核对受影响内容。

完整复核后更新 `document_review` 中的 Markdown 哈希，再运行 `check --require-reviewed`。哈希来自工具输出，不能以填入哈希替代全文核对。

## 完成情况

`ready: true` 表示文件检查通过，且 agent 已记录全部核对工作。最终回复提供目录或 ZIP 链接，并简述实际核对范围。

有 `noted` 限制时，交付说明列出对应页码和对象。遇到无法辨认的正文、缺页或待确认公式，保持相关单元未完成；说明已完成部分、剩余位置及需要补充的信息。
