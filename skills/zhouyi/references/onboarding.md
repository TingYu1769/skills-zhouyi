# 开场与默认

环境检查之后、开工之前，先用几句话告诉用户这一篇会怎么做。说明要短，用户能据此纠正方向，不必读文档。

## 开场说明

同一输出根目录第一次使用（`.zhouyi/` 里还没有通过的环境记录）时，说全四项：

1. **环境与可用模式。** 哪些检查通过、缺什么；有没有 TeX，源码模式能不能用；有没有 pandoc，PDF 模式能不能另出排版好的中文 PDF。
2. **本篇走哪种模式及原因。** 例如“找到 arXiv v7 的同版本源码，走源码模式，交付中文 PDF 和 tex 工程”，或“只提交了 PDF，走 PDF 模式，交付 Markdown 和截图”。
3. **可选项与推荐用法。** 用下文的默认值表，只列用户可能想改的几项。
4. **规模与耗时估算。** 见下文。

之后同一输出根目录再开新的一篇，只报一行，例如：

> 源码模式（找到 arXiv v7 源码）；正文约 3 万字符、14 块，预计 20–50 分钟；沿用已记住的输出目录 `reading/` 和命名约定。

开场之后直接开工，不等确认；只有下文列出的情况才停下来问。

## 默认值

| 事项 | 用户没说明时 |
|---|---|
| 模式 | 能取得同版本 arXiv 源码就走源码模式，否则走 PDF 模式 |
| 输入 | 本地 PDF；只给 arXiv 编号或链接时用 `fetch` 下载，没写版本取最新版 |
| 命名 | `YYYYMM.Venue.ShortName`，输出根目录已有约定时沿用 |
| 范围 | 全文，含附录；参考文献保留英文 |
| 续作 | 有进度就接着做，不重来 |
| 子代理 | 不用；用户要求时才用 |
| 模型 | 当前会话的模型；推荐分工见 [在不同宿主中使用](hosts.md) |
| 提示词框、表格单元 | 保持原文，在最终回复里列出 |
| PDF 模式的交付 | Markdown、原 PDF、`assets/`；有 pandoc 和 XeLaTeX 时另交 `<名>.zh.pdf`；不打 ZIP |
| 中英对照版 | 不交付 |
| 中间产物 | 交付后用 `clean` 清理 |

## 停下来问的情况

- 没给输出根目录，宿主记忆里也没有：给两三个候选（例如 PDF 所在目录、当前目录下的 `reading/`），推荐一个，说明默认的命名结构。
- 源码模式整体走不通（TeX 不可用，或英文底稿编不过且修不好）：请用户在“改走 PDF 模式”“先修环境”“放弃”之间选。
- 需要安装依赖或联网，而宿主没有授权。
- 耗时超出估算的 1.5 倍（见下文）：写完当前单元就停，汇报已完成部分、剩余估算和原因。
- 续作时 `status` 显示工作记录在 30 分钟内被改过，又不是本会话所为：先问用户是否有别的会话在处理同一篇。
- 论文版本与已有工作记录不一致。

其余情况按默认值办，在最终回复里交代。

## 记住用户的选择

周译不写自己的配置文件，用户的选择交给宿主的记忆机制保存，下次开场时先查。记四类：

- 输出根目录与命名约定；
- 花费控制，例如超出估算多少倍时停下；
- 模型分工与是否用子代理；
- 交付偏好：是否打 ZIP、提示词框和表格单元是否补译、中间产物是否保留。

各宿主怎么记，见 [在不同宿主中使用](hosts.md)。宿主没有可用的记忆机制时，每次都按默认值办或询问，并在开场说明里提一句。

## 规模与耗时估算

规模用正文字符数和块数表示：源码模式取 `tex-split` 输出的 `prose_chars` 之和与块数；PDF 模式在建好清单后取正文文字的长度。耗时按每千字符正文 0.3–1.8 分钟估算（单会话主模型、源码模式的实测区间，中位数约 0.8 分钟），开场时给出区间。估算写进工作记录的 `metadata`。

主流宿主都不提供让 agent 在会话中读到自身累计用量的接口，所以“超出估算 1.5 倍”按耗时折算：实际耗时 ÷（预计总耗时 × 已完成的比例）。需要看金额时，请用户用宿主自己的用量命令查看（见 [在不同宿主中使用](hosts.md)）。
